## What to build

Typing a Smart Query ("salon in Pune") and submitting returns real Nominatim Places as responsive cards showing name, Category, and address - with designed shimmer skeletons while loading, an illustrated empty state offering example-query pills, and an error state with retry. Queries are shareable via /search?q=; first load preloads a default query ("cafes in Pune"); category chips under the box run prefilled Smart Queries. All upstream calls flow through one proxied route handler that sets a descriptive User-Agent, serializes requests (~1 req/s), caches at platform level (s-maxage ~60s) plus in-process LRU, and normalizes both parse paths into one Place shape. Vitest tests exercise this handler seam with recorded fixtures: parse-or-verbatim routing, normalization, empty/error payloads, cache headers.

## Acceptance criteria

- [ ] "salon in Pune" renders real Place cards; non-matching queries fall through verbatim
- [ ] Loading, empty, and error states all render as designed; retry recovers
- [ ] /search?q= restores exact results on cold load; default query preloaded on first visit
- [ ] Handler tests pass covering parse routing, normalization, empty/error bodies, cache headers
- [ ] Client never calls providers directly; rate limits respected
